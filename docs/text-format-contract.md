# 默认文本格式适配契约

在原文行索引之后、异常结构组合之前增加有限格式适配；只生成分类视图，不修改输入。所有正文和上下文仍为原文 UTF-16 半开区间，按完整物理行返回。内联标题的主体包含同一行的日志头；逐行前缀保留在预览和复制中，不能把连续原文伪造成去前缀拼接文本。

支持明确的 `时间 [线程] 等级 logger - payload`、`时间 等级 [线程] logger - payload`；等级也允许方括号。时间为日期可选的 HH:mm:ss（可含小数及时区），logger 为 Java 标识符/包名。无时间的 `等级 logger - payload` 仅支持 payload 直接为 Throwable 标题及后续结构，不赋予任意多行消息归属证据。

- payload 必须直接是完整 Throwable 标题，或在消息后的明确 ` : ` / ` - ` 分隔符后为带包名和 Exception/Error/Throwable 后缀的标题。普通提及异常名不触发识别。
- 逐行前缀只在相同布局、线程、等级和 logger 下接纳合法异常结构；时间必须一致；时间变化视为新事件，不猜测跨时间归属。前缀后的空格/tab 缩进保持。不同线程/等级/logger 或混合有前缀与无前缀结构必须停止并报告歧义，不跨日志事件吞并。
- 多行消息必须由同一分支合法且缩进更深的首个调用帧封闭。前瞻最多检查标题后的 256 个物理行，首帧计入上限。新日志事件、独立标题、损坏结构、进程结束和前缀变化都会阻断。逐行相同的带时间前缀可作为同一候选事件的证据。
- 缺少事件或框架证据时，带 Exception、Error 或 Throwable 后缀的独立标题、JVM 线程异常标题、有效的 `Caused by` 和 `Suppressed` 标题仍可按首帧位置推定陌生消息。普通类名形状的标题需要相邻堆栈结构或已有事件证据。首帧后的普通文本保持在该分支范围外。
- MyBatis 和 MySQL 的已知诊断仍可作为消息证据。Spring JDBC `BadSqlGrammarException` 中，同缩进的 MyBatis 诊断和紧接合法首帧的 `; bad SQL grammar []` 摘要都可提供格式证据。其他诊断措辞仍可走通用推定。
- 推定成功时，主体返回包含原文消息与堆栈的连续范围，并标记 `INFERRED_MESSAGE`。结果的 `inferredMessageLines()` 汇总各分支按位置接纳的文本行。空行随消息保留，只有空行的间隔按空行计数。搜索触及上限且还有原文可查时报告 `MESSAGE_LOOKAHEAD_LIMIT`。
- 无可区分标记的交错文本可能被归入首帧前的消息。完整打印的堆栈文本也可能来自样例或测试输出。使用预览中的推定行数和按行调整能力核对范围。

内联标题所在行已经带有事件头，因此不把它前面的独立ERROR事件附为上下文；原始无前缀标题仍沿用相邻ERROR上下文契约。

回归覆盖未知导入诊断、SQL 诊断改写、嵌套分支、普通日志提到异常名、相邻独立标题、不同线程前缀、损坏帧和前瞻上限。测试核对 LF/CRLF、中文和 emoji、内部锚点以及可选上下文。

参考 [Filebeat 官方 Java multiline 与时间头事件示例](https://www.elastic.co/docs/reference/beats/filebeat/multiline-examples)。仅借鉴事件头作为边界证据的概念，未复制第三方代码/正则，未引入 Filebeat/ELK；其通用行合并不能替代 Throwable 分支结构判断。
